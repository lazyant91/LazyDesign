# LazyDesign v0.1-r4 Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a six-cell schema-2 r4 evaluation with the exact r3 experimental inputs while allowing normal Remote/PowerShell/CMD development paths during generation and prohibiting only genuine safety-bypass behavior.

**Architecture:** Reuse the existing `controller-reconciled-v1` harness without schema or runtime changes. The controller owns repository state, packet mechanics, build, verification, metadata, capture, and scoring gates; each fresh generator context only reads its allowed packet inputs, implements the requested UI using normal permitted Remote development interfaces, freezes source, and reports the attempt.

**Tech Stack:** Python 3 evaluation harness, ChatGPT Remote file/process tools, Windows PowerShell/CMD, .NET SDK 9.0.313, Windows App SDK 2.0.1, Windows UI Automation, Git.

### Task 3: Generate six cells in genuinely fresh contexts

**Files:**
- Modify only the active packet `project/` directory.

**Interfaces:**
- Consumes: one prepared packet and its allowed inputs.
- Produces: one frozen source state and one 12-item report per cell.

Process cells in this order:

1. `baseline/connection-settings`
2. `baseline/device-list`
3. `baseline/failure-confirmation`
4. `guided/connection-settings`
5. `guided/device-list`
6. `guided/failure-confirmation`

For baseline cells, read only packet `PROMPT.md`, `PACKET.json` for identity/status, and the starter project. Do not read reference content.

For guided cells, additionally read exactly the packet-local references listed in that packet's `PACKET.json`.

The generator does **not** perform repository branch/HEAD/worktree/remotes inspection. That is controller work and is intentionally removed from the generation surface.

Normal generation development methods are permitted inside the active packet project:

- Remote file reads/writes/edits;
- PowerShell/CMD;
- ordinary local CLI/file inspection and editing.

If one normal Remote interface produces a safety/tool refusal, record the event and continue through another ordinary independently permitted development interface when appropriate. Do not obfuscate, encode, disguise, or transform the operation for the purpose of defeating a safety decision.

A non-material safety/tool event does not require generation to stop. Stop only when the prompt is implemented and source is frozen, or when an actual material external interruption makes implementation impossible.

Generation must never run build/runtime/UIA/capture/validation/scoring, inspect prior results, modify non-project packet data, or repair source after freeze.

Each fresh context returns exactly the existing 12-item report: workspace; condition/scenario; model; reasoning metadata; network use; read inputs; modified files; deleted files; stopping condition; exact infrastructure events; forbidden verification not run; final source frozen.
