# Static review evidence

Method: Read-only review of frozen generated `MainWindow.xaml` and `MainWindow.xaml.cs` against the exact `PROMPT.md`, after the one-shot controlled build. No generated source was repaired.

Observed source structure:
- Native `InfoBar` is present with `Severity="Error"`, title `연결 실패`, the exact required Korean failure message, `IsClosable="True"`, and a native Retry `Button` in `InfoBar.ActionButton`.
- Native `ContentDialog` is present and identifies `거실 스피커`; it provides `PrimaryButtonText="Remove"`, `CloseButtonText="Cancel"`, `DefaultButton="Close"`, and a `Closed` handler intended to return focus to `RemoveDeviceButton`.
- `AutomationProperties.Name` is supplied for Retry, Remove device, and the confirmation dialog.
- No custom `ControlTemplate` is defined.
- Supporting C# opens the dialog, reopens the InfoBar on Retry, and attempts focus return after dialog close.

Compile-blocking defect preserved as generated:
- `MainWindow.xaml.cs` awaits `RemoveDeviceDialog.ShowAsync()` but the generated file imports only `Microsoft.UI.Xaml` and `Microsoft.UI.Xaml.Controls`.
- The controlled compiler reports CS4036 because `IAsyncOperation<ContentDialogResult>` has no resolved `GetAwaiter` extension in this compilation context; the subsequent XAML compiler MSB3073 is a cascading build failure.
- Because the evaluation contract forbids repair, this defect was not corrected and the app was not launched.

Result: static review fails because the generated implementation contains a compile-blocking source defect even though the requested native control structure is present.
